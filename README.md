# Онлайн челленджи

Android-приложение и публичный сайт для челленджей по активности: шаги, пробежки,
сон, отжимания, приседания, планка, пресс, чистка зубов, домашняя работа, танцы,
футбол, лыжи и коньки. Участники ставят измеримые цели, каждый день вносят
результат и получают баллы: фото/видео или галочка другого участника
подтверждает выполнение. Челленджи могут быть общими или приватными: данные
приватного челленджа шифруются, а на сайте по нему видны только имена, очки и
места.

- Сайт: <https://romanlyavin.github.io/online-challenges/>
- APK: [OnlineChallenges-1.6.6.apk](OnlineChallenges-1.6.6.apk) · [последний релиз](https://github.com/RomanLyavin/online-challenges/releases/latest)
- Пакет: `com.onlinechallenges.app`
- Минимальная версия Android: 8.0 (API 26), целевая — API 35

## Возможности

- Регистрация и вход по email и паролю через Supabase Auth — и в приложении,
  и в веб-версии на этом сайте.
- Подтверждение регистрации шестизначным кодом из письма (или ссылкой — как в
  приложении, так и на компьютере). Кнопка «Забыл пароль» отправляет код, после
  ввода которого можно задать новый пароль.

## Как начисляются баллы

Один балл даётся за каждую **полностью выполненную цель**, к которой приложено
подходящее подтверждение: фото/видео или галочка другого участника. Частичный
результат баллов не даёт, превышение цели ничего не добавляет.

| Режим | Период | Как считается |
| --- | --- | --- |
| «Каждый день» | Каждый день челленджа | Балл за каждую цель, выполненную в этот день |
| «Каждые N дней» | Окно из N дней | Результаты внутри окна складываются, балл за каждую закрытую цель |
| «Всего за период» | Весь челлендж | Балл за каждую цель, накопленная сумма по которой достигла цели |

Как подтвердить результат:

- **Фото** — для шагов, пробежки, сна, чистки зубов, домашней работы, лыж,
  коньков и других целей с типом «Фото».
- **Видео** — для отжиманий, приседаний, планки, пресса, танцев, футбола и
  других целей с типом «Видео».
- **Фото или видео** — для целей с типом «Любое».
- **Галочка участника** — подходит для любой цели. Автор отметки не может
  подтвердить сам себя. Подтверждение ставится отдельно по каждой цели и
  действует, пока результат не изменён. Снять галочку можно до окончания
  челленджа; после финиша результаты не меняются.

Цвета дневника: зелёный — все цели периода закрыты, жёлтый — есть частичный
прогресс, красный — период пропущен. После окончания челленджа первые три места
получают медали, которые отображаются в профиле и на сайте.

## Приватные челленджи

При создании челленджа выберите доступ «Общий» или «Приватный».

- Автор приватного челленджа получает код приглашения вида
  `OC1.<id>.<ключ>` на странице челленджа и передаёт его участникам.
- Ввод кода — это и есть приглашение: отдельного сервера, заявок и одобрения
  нет. Код содержит ключ шифрования, поэтому его нельзя публиковать.
- В публичном `data/challenges.json` от приватного челленджа остаётся только
  заглушка: id, название, видимость и время изменения. Посторонние в приложении
  видят название и метку «Приватный», без дат, целей и участников.
- Полные данные лежат в `data/private/<id>.enc`, медиа — в
  `data/private/<id>/media/<id>.enc`. Всё зашифровано AES-GCM; ключ есть только
  на устройствах участников.
- На сайте по приватному челленджу публикуются только имена, очки и места.
  Цели, даты, результаты, фото, видео и подтверждения на сайт не попадают.
- Название приватного челленджа и факт его существования видны публично — это
  цена заглушки в общем репозитории. Если код попал к посторонним, сменить ключ
  в приложении пока нельзя: создайте новый приватный челлендж.
- Организатор может изменить дату окончания или удалить челлендж. Удаление
  убирает заглушку, шифрованный бандл, отметки и подтверждения; у участников
  челлендж исчезает после синхронизации.

## Данные и публикация

Приложение синхронизирует данные в репозиторий:

| Путь | Содержимое |
| --- | --- |
| `data/catalog.json` | Общий каталог активностей и иконки |
| `data/challenges.json` | Общие челленджи полностью, приватные — только заглушки, список удалённых id |
| `data/profiles.json` | Профили, аватары и медали (без приватных медалей) |
| `data/checkins.json` | Отметки и результаты только общих челленджей |
| `data/confirmations.json` | Взаимные подтверждения только общих челленджей |
| `data/standings.json` | Готовый рейтинг для сайта |
| `data/private/<id>.enc` | Шифрованный бандл приватного челленджа |
| `data/private/<id>/media/<id>.enc` | Шифрованные фото и видео приватного челленджа |
| `catalog/icons/<id>_<время>.jpg` | Фото-иконки активностей |
| `confirmations/<код>/<челлендж>/` | Фото и видео общих челленджей |
| `avatars/<код>_<время>.jpg` | Аватары участников |

Сайт читает только `data/standings.json`, поэтому ему не нужен сервер.
Демо-профили `D-ANNA`, `D-MIKE`, `D-IRINA`, `D-DENIS` и демо-челленджи
`demo-active`, `demo-finished` исключаются из синхронизации.

> Репозиторий и сайт публичные по замыслу проекта. Всё, что опубликовано в
> общих челленджах, видно всем: не загружайте туда документы, адреса и другие
> личные данные. Приватные файлы зашифрованы, но код приглашения содержит ключ —
> передавайте его только участникам.

## Настройка синхронизации

1. Установите APK и зарегистрируйтесь. Код подтверждения появится на экране.
2. Заполните профиль.
3. Откройте **Настройки → Синхронизация** и включите автосинхронизацию, если
   нужно отправлять изменения сразу после сохранения.
4. Нажмите «Синхронизировать» на главном экране или в настройках.

При синхронизации приложение сначала читает удалённые JSON, объединяет их с
локальными данными, затем загружает новые медиафайлы и пересобирает
`standings.json`. Если файл уже существует, приложение автоматически получает
его версию (`sha`) и повторяет загрузку.

Ограничения медиа: видео сжимается до 720p (видео ~1,5 Мбит/с, звук AAC
96 кбит/с), итоговый файл — до 25 МБ, исходный — до 300 МБ. Исходное фото — до
40 МБ (сжимается до 1800 px), аватар — до 8 МБ. Файлы больше 35 МБ не
отправляются в GitHub.

## Обновление приложения

**Настройки → О программе → Обновить** проверяет последний релиз на GitHub.
Если версия новее, приложение предложит скачать APK, проверит пакет и подпись
и запустит системный установщик. Для установки может потребоваться разрешение
«Установка неизвестных приложений». Обновление ставится поверх текущей версии
только с той же подписью.

## Структура проекта

```
app/                  Android-приложение на Kotlin + Jetpack Compose
  src/main/java/      Экраны, модели, подсчёт баллов, GitHub-синхронизация
  src/test/java/      Unit-тесты движка челленджей и приватности
web/                  Веб-версия на React + Vite (личный кабинет, реакции)
supabase/             SQL-миграция и проверка RLS для реакций
assets/               Стили, скрипты и favicon прежней статической страницы
data/                 JSON, который создаёт и обновляет приложение
confirmations/        Фото и видео подтверждения
index.html            Статическая страница (заменена сборкой из web/)
```

Пустые JSON в `data/` — это корректные placeholder-файлы для первого запуска
сайта. Приложение заменит их при первой синхронизации. Вручную редактировать
эти файлы не нужно.

## Настройка Supabase

Проект создаётся в [Supabase Dashboard](https://supabase.com/dashboard).

1. **Project Settings → API Keys** —
   <https://supabase.com/dashboard/project/ВАШ-ID/settings/api-keys>. Скопируйте
   **Publishable key** (`sb_publishable_...`). Ключи `sb_secret_...`, `service_role`
   и любые secret keys в приложение и репозиторий не добавляются. Тот же ключ
   виден в диалоге **Connect**: <https://supabase.com/dashboard/project/ВАШ-ID?showConnect=true>.
2. **Authentication → Providers → Email** —
   <https://supabase.com/dashboard/project/ВАШ-ID/auth/providers>. Включите Email,
   подтверждение по ссылке (Confirm email) и отключите только если нужен локальный
   режим без почты.
3. **Authentication → URL Configuration** —
   <https://supabase.com/dashboard/project/ВАШ-ID/auth/url-configuration>:
   - Site URL: `https://romanlyavin.github.io/online-challenges/`
   - Redirect URLs: `com.onlinechallenges.app://auth` и
     `https://romanlyavin.github.io/online-challenges/*`

   Именно Redirect URLs решает, куда Supabase отправит пользователя после
   перехода по ссылке из письма. Если записи нет, ссылка сброса откроет страницу
   Supabase в браузере и останется пустой — приложение не получит управление.
   Добавьте оба адреса в список и нажмите **Save**.
   Если включена опция **Secure email change**, при смене email подтверждение
   нужно пройти по ссылкам и со старого, и с нового адреса.

4. **SQL Editor** — выполните миграцию
   `supabase/migrations/20261127000000_checkin_reactions.sql` (создаёт таблицу
   реакций с RLS). Полные шаги и шаблоны писем с кодом `{{ .Token }}` — в
   `supabase/README.md`. Шаблоны содержат и код, и ссылку, чтобы старый поток
   приложения продолжал работать.

Письма подтверждения и сброса можно открывать где угодно: веб-версия принимает
шестизначный код с компьютера, приложение — код или ссылку
`com.onlinechallenges.app://auth` на телефоне. Если браузер показывает пустую
страницу или `See Other`, нажмите ссылку на этой странице или введите код вручную.

В корне проекта создайте `local.properties` (файл не попадает в Git) со следующим блоком:

```properties
SUPABASE_URL=https://ВАШ-ID.supabase.co
SUPABASE_PUBLISHABLE_KEY=sb_publishable_ваш_ключ
```

Допустимо старое имя `SUPABASE_ANON_KEY` вместо `SUPABASE_PUBLISHABLE_KEY` — сборка
поддерживает оба. URL указывается без `/rest/v1`: SDK ждёт корень проекта.

## Сборка

Нужны JDK 17 и Android SDK с platform/build-tools 35.

```powershell
$env:JAVA_HOME = "путь\к\jdk-17"
$env:ANDROID_HOME = "путь\к\android-sdk"

.\gradlew.bat :app:lintRelease --console=plain
.\gradlew.bat :app:assembleRelease --console=plain
```

## Ограничения

- Без подключённого Supabase регистрация работает локально: подтверждение email
  и восстановление пароля недоступны. Для работы с почтой нужен Supabase-проект
  с включённым провайдером Email и разрешённым redirect URL.
- Нет серверной модерации: корректность результатов проверяют другие участники
  челленджа — галочкой или просмотром фото/видео.
- Синхронизация работает через GitHub Contents API и требует токен с правом
  записи. Конфликты разрешаются по времени последнего изменения и объединению
  участников; одновременная запись с нескольких устройств может потребовать
  повторной синхронизации.
- Приложение и сайт не собирают аналитику. Сторонние компоненты — Supabase Auth
  (вход и письма) и сетевые запросы к GitHub (синхронизация).
